# One exact delivery append profile

This source composition is selected only by `coordinated-witness-delivery-append`.
It is incompatible with `cancel-only-witness-review` and with bootstrap CI fault
instrumentation. The inert bootstrap and cancel-only profiles retain their
separate, nonconvertible APIs. No execution, setup, installation or deployment is
performed by this source change. Compilation/pure tests do not qualify real
Wayland input, installed trust, source opening, mTLS or a journal append.

## Exact ownership

The unchanged actual entry hardens and pins the whole image, then privately
creates C → H + 13 purpose-named W branches and H → S1/S2 before runtime threads,
GUI or source access. Initial launch must be trusted, uninjected and free of
ambient credentials. Clearing environment pointers does not erase inherited
secret memory. The original 30-second bootstrap ceiling and all-forks barrier
remain unchanged. The 13 W branches conservatively preserve the existing
supplied-originals-to-completed-pair lifetimes, not account construction/recovery.

Only original Owner1V3DeliveryAdmission enters the positive Authority adapter.
All other W branches and H/S remain inert and retain their original direct
relationships. W alone opens the selected existing namespace, key paths, TLS
configuration and original source. C receives only ordinary selector data and a
bounded complete presentation. Real source preparation may perform protected
opener/sidecar work and bind a listener; cancellation is not a claim that opening
had no effects. There is no public positive prepare/source factory.

After the barrier, positive C creates exactly 16 additional check-only FDs:
14 root-child pidfds plus the selected W pidfd and socket duplicate. W creates
two check-only original-C edge FDs. These counts are additional to the fixed
bootstrap inventory, not a claim that GUI/TLS opens no further descriptors.
Reapers remain with the sole endpoint/tree owner, never the native issuer.
Observation copies have no public I/O/FD getter. Terminal endpoint disposal
actively shuts down the original socket and latches shared loss, so copies cannot
keep a discarded endpoint artificially live. All retained original lifetimes are
checked without waiting during native Arm/A. No late fork, exec or replacement
is introduced.

## One native slot and one actual effect

The private C window is `org.wholepact.CoordinatorDelivery`. It collects the same
12 ordinary path/public-selector fields as the source adapter. Complete packets
and the complete display must fit 64 KiB; oversize data is rejected, not truncated.
Authority validates the complete presentation digest, exact source/account/head,
request, terms and corrected conditional notice. Ordinary DTOs are not authority.

The genuine visible review sequence is full scrollable display, Continue,
acknowledgment and a focused final primary-button click. That click consumes the
original authenticated opaque review ticket to Arm exactly one conditional
append. It is not A, a legacy Window decision or an effect permit. W then accepts
one original owner-mTLS exchange and releases its first preflight locks before
publishing its exact dynamic Ready.

A occurs only when the private visible native loop consumes that same Armed slot
and authenticated opaque Ready after the full immutable raw input batch and all
Cancel widgets. Discarded, sizing, hidden and repeated frame passes cannot admit.
No second human prompt is inserted into the original accepted TLS interval. The
native issuer is thread-bound, non-Clone and lock-free. It uses exact immutable
shared binding identity and a one-use atomic state transition, never caller
booleans, focus RPC, claimed FD/PID, editable review data or a queued click.

R before A permanently consumes the slot. R after A retains the exact sealed
outbound grant; the endpoint driver only transports that already admitted grant
before later Cancel on the ordered original channel. A failed send is terminal,
not permission to retry. W constructs its opaque FinalAdmit only on the actual
matching authenticated receive. Authority independently checks its retained
source, first preflight ticket, real TLS peer, expected head and original clocks
before its local publication/commit path. Cancel-only custody cannot convert.

The wall and monotonic preparation clocks remain original. C captures an extra
restriction-only 120-second ceiling before queueing Prepare; the driver and origin
can only shorten it. Arm/Ready never renew it. W supplies its original actual
review and accepted TLS Instant values, not reconstructed wire clocks. Review,
TLS and the pre-fork five-minute session ceiling remain independent bounds.

## Outcomes, diagnostics and disposal

Blur, close, Escape, missing/unexpected viewport, clock regression/expiry or an
original peer loss irreversibly clears C's presentation and prevents new admission.
Every explicit blur in the original batch counts even if final focus is true.
An admitted attempt remains potentially in flight until an authenticated exact
outcome proves Committed or KnownNoEffect. Missing outcome after admission is
Uncertain. Cleanup failure does not overwrite a recorded effect classification.

A finite first-failure stage/class may be sent once from the real W operation.
It contains no arbitrary strings, paths, keys, request bytes or exception text.
It is diagnostic only, does not create a ticket/permit and never rewrites the
independently recorded effect outcome. The same positive artifact supports
cancel-before-Arm, blur and at-most-one-append paths without converting profiles.

W sends Disposed only after actual worker completion/join and owned source/TLS
fields drop. It consumes the terminal Cancel before returning to generic STOP.
C uses one capped five-second cleanup attempt, not a fresh budget per message or
child. A blocked worker may force termination without confirmed source disposal.
The native event thread never joins/reaps; main retains the sole driver externally
and joins after eframe returns. Exact-pidfd termination and final kernel reap can
still be unbounded in kernel uninterruptible state; no wall-time reap guarantee
is claimed. A positive-profile zero exit describes the session's terminal cleanup,
not payment readiness or evidence that an append occurred. Other profiles retain
exit 78. No Signer/payment dispatch/financial continuation adapter is enabled.
